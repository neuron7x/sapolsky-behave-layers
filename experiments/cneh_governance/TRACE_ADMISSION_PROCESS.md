## Зафіксований протокол

База `9b6f0a95aff23304927fe8b2dc40f1fa25d1f37a`. У `scripts/cneh_evidence_admission.py` нативний крок порівнює `transition_mode` та `applied_gain` зі значеннями без достатньої перевірки типу. Python ототожнює `False == 0` та `True == 1.0`. Тестуємо незалежно від автентичності історичного архіву, використовуючи малу нативну трасу із задекларованими значеннями струмів, режимом і нульовою рекурентною відповіддю.

| Контроль | Очікування |
|---|---|
| Справна нативна траса | Стабільний хеш попереднього формату. Цілі й дійсні числові значення зберігають попередню валідну семантику. |
| `transition_mode=false` замість цілого нуля на такті 1 | `TRACE`, індекс 1 |
| `applied_gain=true` замість одиничного коефіцієнта на такті 2 | `TRACE`, індекс 2 |
| Одночасні порушення на тактах 1 і 2 | Лише перша невідповідність визначає `trace_tick=1` |
| Написаний у вхідному рядку підроблений номер такту | Індекс береться з фактичної позиції рядка |
| Пошкоджене значення вхідної провідності | `TRACE` із фактичним тактом |
| Порожній або неповний список кроків | `TRACE` без вигаданого номера кроку |
| CLI на відхиленому кроці | exit 2, `failure_code=TRACE`, `trace_tick` за наявності, `scientific_promotion_authorized=false`, жодного успішного акта |

Заморожуємо ці контроли до зміни реалізації. Зберігаємо журнал базового провалу. Критерій рішення — всі нові контроли проходять на кандидатові, стара семисімейна панель і обидва історичні архіви приймаються в обсязі чинного контракту, канонічний PR-гейт проходить. Зміна стосується діагностики та типізації кроку. Вона не надає наукового допуску й не змінює статусу REAL-TRANSFER-01.
