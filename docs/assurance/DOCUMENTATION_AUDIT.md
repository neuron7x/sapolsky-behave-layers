## Audit mechanics and disposition

GitHub Actions audits the checked-out commit using its Git object inventory.
Every tracked blob has a path, mode, size, Git object ID and a classification.
The report distinguishes documentary, evidentiary, verification and source
material. A blob's identity supplies provenance. Pending substantive review is
`INCOMPLETE`. Known open inconsistencies carry their explicit findings.
A repo-wide Markdown scan reports unresolved simple inline relative path links.
The exact byte-for-byte upstream README is checked in its pinned original layout.
Anchors and remote URLs require separate verification. Historical byte identities
and negative outcomes remain available.

| State | Applies when |
| --- | --- |
| VERIFIED | An authorized independent record supports the exact claim, method and evidence. The current gate admits no claim of this class without an issuer policy. |
| INCOMPLETE | The identified material provides partial evidence or requires substantive review. |
| MISSING | An identified required deliverable or outcome is absent from the reviewed scope. |
| INVALID | A demonstrable contradiction invalidates the cited claim or acceptance operation. |
| OUTDATED | The recorded scope or status conflicts with later canonical evidence. |
| NOT_APPLICABLE | The present scope excludes the operation and supplies traceable justification. Commissioning must be re-evaluated if authority changes. |

Run `python -B scripts/documentation_audit.py --output /tmp/cwc-documentation-audit.json`
in a clean full-history checkout. The report and SHA-256 are attached to its
GitHub Actions run. The catalogue command exits 0 on a valid inventory even if
acceptance is blocked. `--accept` returns 3 while required evidence or external
authority is unresolved. Malformed provenance or a corrupt register exits 2.

## Admission of documentation

The [internal review receipt](DOCUMENTATION_REVIEW.json) binds each finding
to the reviewed commit, tree and exact blob. The audit also scans relative links
across tracked Markdown in the audit scope. A missing receipt, changed finding blob or broken
relative link blocks scoped documentation acceptance. That acceptance covers
the recorded technical review. Human peer review, institutional approval and
external replication have their own evidence requirements.

On a valid inventory, `--accept-documentation` exits 0 for scoped documentation
acceptance and 3 if blocked. `--accept` applies the same exit codes to programme
acceptance. Malformed provenance or a corrupt register exits 2.

The audit job tests roster deletion, fabricated verification, misapplied
exclusions, invalid evidence identities, duplicate records, same-count obligation
substitution and broken Markdown targets. The same job damages a WP4 byte,
repeats packaging, checks manifest fields and restored Git bytes and modes, and
checks that packaging rejects a dirty release.
Existing exact-certificate, historical-evidence and experimental gates provide
their own scoped receipts. Open gaps include input admission and model execution,
independent scientific reproduction, complete per-document review, external restoration of a frozen public archive and the authority of any applicable institution. No terminal act is
issued. Interpret a valid negative through its frozen protocol.

## Sequence and responsibility

Discovery and inventory use Git tree identity. Preserve the pinned baseline and
roster commits in the integrated ancestry when accepting this audit. Classification and cross-reference
map obligations to actual records. Findings retain baseline counterexamples.
Candidate remediation is reviewed against the source, then tested on the hosted
checkout. Scientific validation and reproduction are separate acceptance stages.
Owner, venue and independent review decisions must be recorded by the corresponding
authority. The gate refuses acceptance while a required stage is unresolved.
