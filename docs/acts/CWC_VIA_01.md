# CWC-VIA-01 — Vertical Inference Ascension Act

**Status:** EXECUTED THROUGH VIA-V1 ENGINEERING; SCIENTIFIC ASCENSION BLOCKED BY PRIOR KILL RULE
**Programme:** Cognitive Wiring Core (CWC)
**Scope:** causal opportunity → observability → controller → physical execution → temporal adaptation → hierarchy → grand falsification
**Decision authority:** frozen repository evidence and preregistered gates outrank architecture intent.

## 1. Purpose

CWC-VIA converts adaptive-computation research into a vertical, fail-closed inference programme.
The target is not “more dynamic architecture”. The target is a causal chain in which every added
level must earn its own incremental cost:

```
V1 causal opportunity
  -> V2 observable information ceiling
  -> V3 calibrated marginal-value controller
  -> V4 physical conditional execution
  -> V5 stateful adaptation
  -> V6 hierarchical governor
  -> V7 hidden-OOS Pareto falsification
```

No descendant may be implemented as scientific evidence while an ancestor gate is closed.
Scaffolding, test infrastructure, or theory may be prepared, but may not be reported as an
ascension result.

## 2. Prior evidence is binding

The repository already contains a preregistered real-workload kill rule:

- WP18: both real workloads failed `G_lo > c_route`; architecture work was halted.
- WP19: a genuine context × resource interaction appeared on untied depth for prose, but remained
  far below the corrected certificate / route-cost threshold. The decision stayed negative.
- WP-R1: derived the screening condition `Ghat > c_route + kappa*se` for the frozen 3×3 design.

Therefore CWC-VIA-01 **must not** evade the existing result by trying a fourth difficulty proxy,
re-labelling the same task, or searching benchmarks until routing wins.

The implementation in this act consequently does two things only:

1. installs a reusable causal-identification substrate for a future, genuinely new preregistered
   mechanism/workload family; and
2. re-analyses already frozen evidence as a regression/positive-control test of that substrate.

The retrospective audit has a hard class ceiling: it cannot unblock VIA-V2.

## 3. VIA-V1 scientific question

For an independent unit `i`, pre-decision observable context `X_i`, action `a`, scalarized task
utility `Y_i(a)`, and measured control cost `c_ctrl`, test whether context-conditioned action choice
has positive *causal* net value over the best fixed action.

Primary opportunity estimand:

```
G = E_X max_a E[Y(a)|X] - max_a E_X E[Y(a)|X]
```

Primary deployability criterion:

```
LCB(G) > c_observe + c_decide + c_dispatch
```

The units of `Y` and all charged costs must be commensurate before the gate is evaluated. FLOPs,
latency and energy are not silently mixed into a scalar; any scalarization must be preregistered.

## 4. Identification hierarchy

Order of preference:

1. **Exhaustive frozen-action replay** when all actions can be evaluated on the same immutable unit
   without carry-over. This directly observes potential outcomes and is preferred at small scale.
2. **Randomized intervention** with known propensity when exhaustive replay is impossible.
3. **Doubly robust / heterogeneous-effect estimation** only as a secondary estimator, with
   group-preserving cross-fitting. It never substitutes for experimental identification when
   randomization is feasible.

A token is not an independent unit when tokens share a request/document/episode. Cross-fitting and
resampling operate at the highest dependence-preserving unit available.

## 5. Mandatory controls

Every future confirmatory VIA-V1 run must include, where well-defined:

- best fixed action;
- randomized action policy;
- context-label permutation null;
- collapsed-context null;
- interaction-destroyed additive null;
- positive control with a known context × action interaction;
- counterfactual route/action swaps;
- contamination and pre-decision-information checks.

The additive null is decisive: after projecting the utility surface onto context + action main
effects, the oracle gap must be zero up to numerical tolerance.

## 6. Statistical discipline

- Primary inferential unit: request/document/episode (or a preregistered independent higher-level
  unit), never nested tokens by default.
- Existing corrected CWC identifiability bound remains the primary certificate where its
  assumptions apply.
- Maximum cell standard error is used conservatively for a common-SE certificate.
- Any bootstrap/randomization procedure uses fixed preregistered seeds and preserves clusters.
- Multiple candidate mechanisms require family-wise correction and a frozen family definition.
- A retrospective re-analysis cannot promote a claim that the original evidence could not support.

## 7. Reopening criterion after the WP18 kill rule

VIA-V1 may run a *new confirmatory real-workload study* only if all of the following are true before
outcomes are inspected:

1. the mechanism family is scientifically distinct from the two already tested axes (weight-tied K
   and untied depth), not merely a new difficulty feature;
2. the workload family and split are frozen before result inspection;
3. the decision state uses only pre-decision information and its acquisition cost is measurable;
4. a cheap pilot is evaluated by the existing routability screen; and
5. the pilot does not make certification economically impossible under the frozen budget.

If these conditions are not met, the programme stays scientifically halted. Engineering curiosity
is not a reopening criterion.

## 8. Vertical gates

### VIA-V1 — causal opportunity
PASS only if a preregistered held-out lower confidence bound on adaptive opportunity exceeds total
incremental control cost. Current status: **BLOCKED / NOT TESTED on a new admissible mechanism**.

### VIA-V2 — observability ceiling
May start only after VIA-V1 PASS. It must upper-bound extractable value from cheap observable state
before a learned router is trained.

### VIA-V3 — marginal-value controller
May start only after VIA-V2 PASS. Primary metric is oracle/net-utility regret, not routing accuracy.
Uncertainty must permit abstention to the safe fixed policy.

### VIA-V4 — physical conditional execution
May start only after VIA-V3 PASS. Unselected branches must be absent from independent GPU execution
traces. Theoretical FLOP savings alone are not a win.

### VIA-V5 — stateful adaptation
May start only after VIA-V4 PASS. Regime-return tests and deterministic rollback are mandatory.

### VIA-V6 — hierarchical governor
May start only after VIA-V5 PASS. A matched flat controller is the primary architectural null.
If it reproduces the frontier, hierarchy fails.

### VIA-V7 — grand falsification
May start only after all prior gates pass. Hidden OOS workloads and a frozen matched-budget
competitor family are mandatory. A positive claim requires a statistically supported non-dominated
region after all controller, dispatch, memory and hierarchy overheads.
